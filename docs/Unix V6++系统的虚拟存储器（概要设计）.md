## 一、课程设计任务与核心要求

### 1\.1 整体任务

为 Unix V6\+\+ 系统添加完整的虚拟存储器功能，实现虚实地址映射、缺页异常处理、写时复制（COW）、物理页框管理及交换区管理等核心机制。

### 1\.2 核心要求

1. `exec`系统调用执行时，**必须为堆栈分配物理页框，并装入命令行参数**。

2. 其余逻辑页统一由**缺页异常处理程序**分配物理页框并完成初始化。

3. 进程释放物理页框时（如调用`free`、`exit`），必须同步维护**共享页哈希表**和**物理页框 Page 数组**。

4. 实现写时复制（COW）机制，优化`fork`系统调用的内存开销。

## 二、核心数据结构

### 2\.1 进程内存描述符与 vm\_area

进程的虚拟地址空间由**Vm 链表**管理，以链表形式组织；每个逻辑段对应一个`vm_area`控制块，所有`vm_area`按**虚拟起始地址递增排序**。

```c
// 页表项（PTE）定义（Unix V6++原有定义不变）
struct pte {
    P:1;          // 存在位，0表示页面在盘交换区
    u_s: 略;      // 用户/内核态位
    R_W: 略;      // 读写权限位
    base: 物理页号; // 物理页框号（P=1时有效）
    swap_addr: 盘交换区地址; // 交换区块号（P=0时有效，块大小4096字节）
    保留位;
};

// 虚拟段控制块
struct vm_area {
    v_start: 虚拟地址;  // 虚拟段起始地址
    v_length: 长度;     // 虚拟段长度（字节）
    prot: 保护位;       // 包含U/s、R/W、P位
    f_start: 偏移量;    // 该段在文件中的起始地址
    f_length: 长度;     // 该段在文件中的长度
    pgtbl: 页表指针;    // 指向该段对应的页表
    next: struct vm_area*; // 指向下一个虚拟段控制块
};
```

进程的`Process`结构体中通过`user`指针关联到自身的`vm_area`链表头。

### 2\.2 物理页框管理：Page 数组

系统维护全局`Page`数组，每个元素对应一个物理页框，记录其使用状态和共享信息。物理页框分为**空闲**和**已分配**两类，已分配页框根据用途挂接在不同链表上。

```c
struct Page {
    inode: 索引节点指针; // 关联的文件inode（共享页有效）
    count: 引用计数器;   // 该物理页框的引用次数
    pageNo: 物理页号;    // 物理页框编号
    f_offset: 偏移量;    // 对应文件中的页内偏移（4096字节对齐）
    next: struct Page*;  // 哈希表/链表的下一个节点指针
};
```

### 2\.3 共享页哈希表

系统维护一张**共享页哈希表（Shared Page Hash）**，用于管理进程间需要共享的逻辑页，通过`inode`和文件内页号计算哈希值，快速定位共享物理页框。

### 2\.4 盘交换区管理：SwapPage 数组

系统维护全局`SwapPage`数组，每个元素对应盘交换区上的一个页面，记录交换页与物理页、页表的映射关系。

```c
struct SwapPage {
    pageNo: 物理页号;        // 对应物理页框号（若已换入）
    pte_ptr: struct pte*;    // 指向对应进程的页表项
    SwapPageNo: 交换区号;    // 该页在盘交换区上的编号
    next: struct SwapPage*;  // 链表下一个节点指针
};
```

## 三、关键系统调用处理

### 3\.1 exec 系统调用

原有执行逻辑保持不变，新增虚拟内存初始化步骤：

1. 构造进程的`vm_area`链表，分别对应代码段、数据段、BSS 段、堆、栈。

2. **为堆栈分配物理页框，并装入命令行参数**。

3. 清空进程原有页表，建立新的虚实地址映射。

4. 调用返回用户态，执行目标应用程序。

### 3\.2 fork 系统调用

实现写时复制（COW）优化，核心步骤：

1. 复制父进程的`Process`结构体、PPDA（进程数据区）和`vm_area`链表。

2. 为子进程分配独立的页表。

3. 遍历父进程的`vm_area`链表，复制所有页表项（PTE）：

    - 父进程和子进程的**读写位（R/W）均设为只读**。

    - 对应物理页框的`Page[frame].count`引用计数器加 1。

    - 若页面已换出到盘交换区，则直接复制交换区地址，不触发 COW（缺页时直接从交换区调入）。

4. 后续任一进程对页面执行写操作时，触发写时复制缺页异常。

## 四、缺页异常处理程序

### 4\.1 总体功能

1. 识别非法内存访问：遍历`vm_area`链表，检查 CR2 寄存器（存储缺页虚拟地址）是否落在合法虚拟段区间内；若不在且非堆 / 栈扩展请求，则触发段错误。

2. 处理堆、栈的动态扩展请求。

3. 实现写时复制（COW）的缺页处理。

4. 根据不同虚拟段类型，完成页面调入和初始化。

### 4\.2 不同段的缺页处理逻辑

#### 4\.2\.1 代码段 / 只读数据段

1. 计算缺页虚拟地址在文件中的偏移量：`offset = vm_area.f_start + (cr2 - vm_area.v_start)`。

2. 计算文件内页号：`file_page = offset >> 12`。

3. 获取对应文件的`inode`指针，计算哈希值：`hash = hash(inode, file_page)`。

4. 遍历共享页哈希表，搜索匹配的`inode`和文件页号：

    - **哈希命中**：直接使用该物理页框，`Page[frame].count++`，建立页表映射并刷新 TLB。

    - **哈希未命中**：

        1. 分配空闲物理页框`frame`。

        2. 调用`readi`函数启动 I/O，从文件读入对应页面。

        3. 初始化`Page[frame]`结构体，将其插入共享页哈希表头部。

        4. `Page[frame].count = 1`，建立页表映射并刷新 TLB。

#### 4\.2\.2 数据段

1. 先按照**代码段逻辑**从文件调入原始页面到物理页框`frame1`，并插入共享页哈希表。

2. 再分配一个新的物理页框`frame2`，将`frame1`的内容完整复制到`frame2`。

3. 将`frame2`挂接到当前进程的页表，建立地址映射（仅当前进程可见）。

4. 若原页表项非空（父进程页面已换出），则先从交换区调入页面，再执行上述复制步骤。

#### 4\.2\.3 BSS 段

- **首次访问**：分配物理页框，**必须将页框内容清零**，建立页表映射。

- **非首次访问**：触发写时复制逻辑，处理方式同数据段。

- 注意：全程维护共享页哈希表和`Page`数组的引用计数。

#### 4\.2\.4 堆栈段

- **首次访问**：分配物理页框（无需清零），建立页表映射。

- **非首次访问**：触发写时复制逻辑，处理方式同数据段。

#### 4\.2\.5 堆扩展

- **首次访问扩展区域**：分配物理页框，更新对应`vm_area`的`v_length`字段，建立页表映射。

- **非首次访问扩展区域**：触发写时复制逻辑。

## 五、物理页框释放与资源回收

1. 进程调用`free`释放堆内存、或调用`exit`终止时，遍历自身的`vm_area`链表，逐个释放关联的物理页框。

2. 释放页框时：

    - 将`Page[frame].count`引用计数器减 1。

    - 若`count`减至 0，则将该页框从共享页哈希表中移除，并加入系统空闲页框链表。

    - 清空对应页表项，刷新 TLB。

3. 若页面已换出到交换区，则同时释放交换区对应的`SwapPage`条目。

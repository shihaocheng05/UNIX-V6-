## 一、虚拟存储器概述

### 1\.1 定义与核心思想

虚拟内存（Virtual Memory）是现代操作系统的核心机制之一，它通过将物理内存（RAM）与磁盘存储结合使用，为每个进程提供**连续、独立且远大于实际物理内存**的地址空间。所有进程共享统一的内存视图，极大简化了编译器和应用程序的内存管理复杂度。

### 1\.2 核心优势

- **扩展可执行存储器容量**：支持运行虚空间大于物理内存总量的应用程序

- **提高系统并发度**：减少单进程内存占用，支持更多进程同时驻留内存

- **简化内存管理**：进程无需关心物理内存的实际分布

- **提升加载速度**：采用惰性分配策略，无需一次性加载全部进程映像

### 1\.3 理论基础：程序局部性原理

请求调页技术的可行性完全依赖于程序运行的局部性规律：

- **时间局部性**：当前执行的指令 / 访问的数据，不久后很可能再次被访问（源于循环结构）

- **空间局部性**：与当前访问的指令 / 数据相邻的存储单元，近期被访问的概率极高（源于指令顺序执行、数组等数据结构的连续存储）

传统一次性内存分配方式违背了局部性原理，会导致物理内存利用率低下、进程加载速度慢、系统并发度低等问题。

## 二、虚拟存储器核心原理

### 2\.1 地址空间分离

- **虚拟地址空间**：每个进程独立拥有的等长连续地址空间（如 32 位系统为 4GB），与物理内存实际分布无关

- **物理地址空间**：真实硬件内存的地址空间，由操作系统统一管理，为所有进程共享

### 2\.2 分页机制

虚拟内存普遍采用分页技术实现虚实地址映射：

1. 将虚拟地址空间划分为固定大小的**页（Page）**（通常为 4KB）

2. 将物理内存划分为同样大小的**页框（Frame）**

3. 操作系统通过**页表（Page Table）**、内存描述符及其他内核数据结构，建立虚拟页与物理页框 / 磁盘空间的映射关系

### 2\.3 按需加载（请求调页）

物理页框的分配延迟至进程**实际访问**某个虚拟页时才执行，即 "惰性内存分配"：

1. 进程使用虚拟地址（VA）访存时，通过`page = VA >> 12`计算页号并查找对应页表项（PTE）

2. 若 PTE 的`Present(P)`位为 1：表示该页已在内存，直接使用 PTE 中的物理页框号进行地址映射

3. 若 PTE 的`Present(P)`位为 0：触发缺页异常，由内核异常处理程序分配物理页框、初始化页内容并更新页表

### 2\.4 页面置换机制

当物理内存不足时，操作系统通过特定算法选择一个暂时不用的页面换出到磁盘交换区，腾出空间给新页面。页面置换是虚拟内存系统能够 "超越" 物理内存限制的关键。

## 三、硬件支持机制

### 3\.1 MMU（内存管理单元）

CPU 执行单元给出虚拟地址后，MMU 负责完成两项核心工作：

1. **内存保护**：检查访问权限是否合法

2. **地址映射**：将虚拟地址转换为物理地址

### 3\.2 页表项（PTE）结构（4KB 页）

32 位 x86 架构下的页表项结构如下（位从 0 到 31）：

|位段|含义|说明|
|---|---|---|
|0|Present\(P\)|页面是否驻留内存：1 = 在内存，0 = 不在内存|
|1|Read/Write\(R/W\)|读写权限：0 = 只读，1 = 可读写|
|2|User/Supervisor\(U/S\)|特权级：0 = 内核态，1 = 用户态|
|3|Write\-through\(PWT\)|写通模式|
|4|Cache disabled\(PCD\)|禁用缓存|
|5|Accessed\(A\)|访问位：页面被访问时硬件自动置 1|
|6|Dirty\(D\)|修改位：页面被写入时硬件自动置 1|
|7|Page Size\(PS\)|页大小：0=4KB，1=4MB|
|8|Global\(G\)|全局页标志|
|9\-11|Avail|系统程序员可用|
|12\-31|Page Base Address|物理页框基地址（高 20 位）|

### 3\.3 缺页异常错误码

x86 架构触发 14\# 缺页异常时，硬件会将错误码压入栈，各位含义如下：

|位|含义|说明|
|---|---|---|
|0|P|0 = 缺页由页面不存在引起；1 = 缺页由权限违例引起|
|1|W/R|0 = 读访问引发异常；1 = 写访问引发异常|
|2|U/S|0 = 内核态访问引发异常；1 = 用户态访问引发异常|
|3|RSVD|0 = 未保留位违例；1 = 页表项保留位被置 1 引发异常|

### 3\.4 硬件地址映射流程

1. 用虚拟地址的页号查找当前进程的页表，定位对应的 PTE

2. 若 PTE 不存在或 P 位为 0，抛出 14\# 缺页异常

3. 权限检测：

    - 用户态访问 U/S 位为 0 的页面，抛出异常

    - 写操作访问 R/W 位为 0 的页面，抛出异常

4. 用 PTE 中的物理页框号与虚拟地址的页内偏移量拼接成物理地址

5. 硬件自动更新 PTE：访问位 A 置 1，写操作时修改位 D 置 1

## 四、Linux 虚拟内存实现

### 4\.1 进程虚拟内存布局（32 位系统）

```Plain Text
0xFFFFFFFF  +-----------------+
            | 内核空间（1GB） | 所有进程共享，包含内核代码、数据、PCB等
0xC0000000  +-----------------+
            |                 |
            |    用户栈       | 向下增长
            |                 |
            +-----------------+
            |    堆（动态内存）| 向上增长
            +-----------------+
            |    BSS段        | 未初始化全局变量，自动清0
            +-----------------+
            |    数据段       | 已初始化全局变量
            +-----------------+
            |    只读数据段   | 常量、字符串字面量
            +-----------------+
            |    代码段       | 可执行指令
0x08048000  +-----------------+
            |                 |
0x00000000  +-----------------+
```

用户空间被划分为多个独立的**虚拟内存区域（VMA）**，每个区域由`vm_area_struct`结构体管理。

### 4\.2 核心数据结构

Linux 通过三级结构管理进程虚拟内存：

1. **task\_struct**：进程控制块，包含指向内存描述符的指针`mm`

2. **mm\_struct**：内存描述符，管理整个进程的虚拟地址空间，包含：

    - 页目录基地址`pgd`

    - 虚拟内存区域链表头`mmap`

3. **vm\_area\_struct**：虚拟内存区域控制块，描述一个连续的虚拟地址范围，包含：

    - 起始地址`vm_start`和结束地址`vm_end`

    - 保护位`vm_prot`（U/S、R/W 等）

    - 标志位`vm_flags`

    - 指向文件的指针（若为文件映射区域）

    - 链表指针`vm_next`

**物理内存管理**：

- 系统维护全局`Page`数组，每个元素对应一个物理页框，记录页框的使用状态、引用计数、所属文件等信息

- 采用基树（Radix Tree）管理文件页缓存，快速查找文件对应的物理页框

### 4\.3 不同虚拟内存区域的缺页处理

用户空间逻辑页存在三种状态：不存在、存在（有物理页框）、不存在（等待分配）。不同区域的物理页框初始化方法不同：

#### 4\.3\.1 代码段 / 只读数据段

- 首次访问（PTE 为空）：

    1. 计算逻辑页在文件中的偏移量：`f_offset = cr2 - vm_start + f_start`

    2. 用`f_offset`查找基树，若缓存存在则直接建立映射（共享代码段）

    3. 若缓存不存在，分配物理页框，从磁盘文件读取代码页内容

    4. 更新 PTE，设置保护位为只读，刷新 TLB

- 非首次访问（PTE 非空）：从磁盘交换区换入页面

#### 4\.3\.2 数据段

- 首次访问（PTE 为空）：

    1. 从文件加载全局变量初值到内核缓存页

    2. 分配新的物理页框，复制缓存页内容（写时复制准备）

    3. 将新页框映射到进程页表，设置保护位

- 非首次访问（PTE 非空）：

    - 若为写操作且页引用计数 \> 1：执行写时复制，分配新页框并复制内容

    - 若页引用计数 ==1：直接将 PTE 保护位改为可读写

    - 若页面已换出：从磁盘交换区换入

#### 4\.3\.3 BSS 段 / 堆 / 用户栈

- 首次访问（PTE 为空）：分配物理页框并全部清 0，建立页表映射

- 非首次访问（PTE 非空）：与数据段处理逻辑相同（写时复制或换入）

### 4\.4 缺页异常处理程序完整流程

1. **内存保护检查**：

    - 遍历`vm_area_struct`链表，查找`cr2`（引发缺页的虚拟地址）所在的区域

    - 若未找到：检查是否为堆栈扩展，若是则扩展堆栈；否则判定为非法内存访问，向进程发送`SIGSEGV`信号

    - 若找到但权限不匹配（如写只读页面）：同样发送`SIGSEGV`信号

2. **执行请求调页或写时复制操作**（根据区域类型）

3. 异常返回，重新执行引发缺页的指令

### 4\.5 fork \(\) 创建子进程

Linux 采用 \\*\\* 写时复制（Copy\-On\-Write, COW）\\*\\* 技术实现高效的进程创建：

1. 复制父进程的`task_struct`和`mm_struct`

2. 复制父进程的`vm_area_struct`链表

3. 为子进程分配独立的页目录和页表

4. 将父进程所有可写页面的 PTE 保护位改为只读

5. 增加所有共享物理页框的引用计数

6. 不为子进程分配物理页框，不复制父进程的数据页

当父 / 子进程尝试写入共享页面时，触发缺页异常，执行写时复制操作。

### 4\.6 exec \(\) 加载应用程序

1. 释放原进程的所有虚拟内存区域和物理页框（引用计数减 1）

2. 读取目标可执行文件的程序头

3. 构造新的`vm_area_struct`链表，填入各段的虚拟地址范围、文件偏移等信息

4. 构造新的用户栈，分配物理页框并装入命令行参数

5. 将新用户栈映射到进程页表

## 五、Unix V6\+\+ 虚拟存储器设计与实现

### 5\.1 任务要求

为 Unix V6\+\+ 系统添加请求调页式虚拟存储器，核心要求：

1. `exec`执行时，仅为堆栈分配物理页框并装入命令行参数

2. 其余逻辑页均在缺页异常时由处理程序分配物理页框并初始化

3. 进程释放物理页框时（如`free`、`exit`），必须正确维护哈希表和`Page`数组

### 5\.2 核心数据结构

#### 5\.2\.1 虚拟内存区域控制块（vm\_area）

```c
struct vm_area {
    unsigned int v_start;    // 虚拟地址起始地址
    unsigned int v_length;   // 虚拟地址长度
    unsigned int prot;       // 保护位（U/S, R/W, P）
    unsigned int f_start;    // 文件中起始地址
    unsigned int f_length;   // 文件中长度
    struct vm_area *next;    // 指向下一个vm_area
};
```

- 每个逻辑段对应一个`vm_area`结构体

- 所有`vm_area`按起始地址递增排序，形成链表

#### 5\.2\.2 物理页框描述符（Page）

系统维护全局`Page`数组，每个元素对应一个物理页框：

```c
struct Page {
    struct inode *inode;     // 所属文件的inode（若为文件页）
    unsigned int f_offset;   // 文件中的偏移量（页号）
    unsigned int count;      // 引用计数器
    unsigned int pageNo;     // 物理页框号
    struct Page *next;       // 哈希表链表指针
};
```

#### 5\.2\.3 共享页哈希表

系统维护一张全局哈希表`SharedPageHash`，用于管理进程间共享的逻辑页（如代码段）。通过`hash(inode, page)`计算哈希值，快速查找共享页。

#### 5\.2\.4 交换区管理

系统维护`SwapPage`数组，每个元素对应磁盘交换区的一个页面：

```c
struct SwapPage {
    unsigned int pageNo;     // 对应的物理页框号（若在内存）
    unsigned int swapPageNo; // 交换区上的页号
    struct pte *pte;         // 指向对应页表项的指针
    struct SwapPage *next;   // 链表指针
};
```

### 5\.3 exec 系统调用实现

1. 释放原进程的所有`vm_area`和物理页框

2. 读取目标可执行文件的程序头，构造新的`vm_area`链表

3. 为用户栈分配物理页框，装入命令行参数和环境变量

4. 将用户栈映射到进程页表

5. 其余逻辑段均不分配物理页框，等待缺页时加载

### 5\.4 fork 系统调用实现

1. 复制父进程的`Process`结构、PPDA 和`vm_area`链表

2. 为子进程分配独立的页表

3. 遍历父进程的所有页表项：

    - 若 P 位为 1（页面在内存）：将父进程 PTE 的 R/W 位改为只读，增加对应`Page`的引用计数，复制 PTE 到子进程页表

    - 若 P 位为 0（页面已换出）：直接复制 PTE 到子进程页表

4. 子进程的所有 PTE 初始状态与父进程相同

### 5\.5 缺页异常处理程序

Unix V6\+\+ 缺页异常处理程序实现三大功能：识别非法内存访问、扩展堆栈、请求调页与写时复制。

#### 5\.5\.1 代码段 / 只读数据段缺页

1. 计算逻辑页在文件中的偏移量：`offset = f_start + (cr2 - v_start)`

2. 计算文件页号：`page = offset >> 12`

3. 计算哈希值：`hash = hash(inode, page)`

4. 遍历共享页哈希表查找对应页面：

    - 若找到：直接建立映射，增加`Page`引用计数

    - 若未找到：分配物理页框，从磁盘文件读取页面内容，将页面加入哈希表，建立页表映射

#### 5\.5\.2 数据段缺页

1. 首次访问（PTE 为空）：

    - 从文件加载全局变量初值到一个物理页框（缓存页）

    - 分配第二个物理页框，复制缓存页内容

    - 将第二个页框映射到进程页表

2. 非首次访问（PTE 非空）：

    - 若为写操作且页引用计数 \> 1：执行写时复制

    - 若页面已换出：从交换区换入

#### 5\.5\.3 BSS 段 / 堆 / 用户栈缺页

1. 首次访问：分配物理页框并全部清 0，建立页表映射

2. 非首次访问：与数据段处理逻辑相同

## 六、页面置换算法

当物理内存不足时，页面置换算法决定淘汰哪个页面，目标是尽可能降低缺页率。

### 6\.1 页面置换策略分类

|策略类型|特点|
|---|---|
|固定分配局部置换|为每个进程分配固定数目的物理页框，缺页时只能淘汰自己的页面|
|可变分配局部置换|为每个进程分配一定数目的物理页框，根据缺页频率动态调整，缺页时仍只能淘汰自己的页面|
|可变分配全局置换|为每个进程分配一定数目的物理页框，系统维护全局空闲页框队列，缺页时可淘汰任意进程的页面|

### 6\.2 经典页面置换算法

#### 6\.2\.1 最优置换算法（OPT）

- **原理**：淘汰未来最久不会被访问的页面

- **特点**：理论上缺页率最低，但无法实现（无法预知未来访问情况），仅作为衡量其他算法性能的基准

#### 6\.2\.2 先进先出算法（FIFO）

- **原理**：淘汰最先进入内存的页面

- **优点**：实现简单，时间复杂度 O \(1\)

- **缺点**：

    - 无法保证常用页面不被淘汰，缺页率较高

    - 可能出现**Belady 异常**：分配更多物理页框时，缺页率反而上升

**Belady 异常示例**：
访问序列：3,2,1,0,3,2,4,3,2,1,0,4

- 3 个物理页框：9 次缺页

- 4 个物理页框：10 次缺页

#### 6\.2\.3 最近最久未使用算法（LRU）

- **原理**：淘汰最近最久未被访问的页面（基于时间局部性原理）

- **优点**：性能接近 OPT，缺页率较低

- **缺点**：每次访存都需要维护 LRU 链表，硬件开销极大，无法直接实现

#### 6\.2\.4 Clock 算法（NRU，最近未使用）

LRU 的近似实现，利用硬件提供的访问位 A：

1. 系统维护一个循环队列，每个元素指向一个驻留页面的 PTE

2. 维护一个当前指针`current`

3. 发生缺页时：

    - 若`current`指向的页面 A 位为 0：淘汰该页面

    - 若 A 位为 1：将 A 位清 0，`current`指针后移

    - 重复上述步骤直到找到 A 位为 0 的页面

#### 6\.2\.5 改进型 Clock 算法

结合访问位 A 和修改位 D，优先淘汰干净页面（无需写回磁盘）：
页面按 \(A,D\) 分为四类，淘汰优先级从高到低：

1. \(0,0\)：最近未访问且未修改（最佳淘汰页）

2. \(0,1\)：最近未访问但已修改

3. \(1,0\)：最近已访问但未修改

4. \(1,1\)：最近已访问且已修改

**算法流程**：

1. 第一遍扫描：寻找 \(0,0\) 页面，找到则淘汰

2. 第二遍扫描：寻找 \(0,1\) 页面，将途经页面的 A 位清 0

3. 若仍未找到，重复第一遍和第二遍扫描

### 6\.3 页面缓存算法

现代操作系统普遍采用页面缓存机制：

- 系统维护全局空闲页框池，分为干净缓存队列和脏缓存队列

- 每个进程维护自己的驻留集队列（如 FIFO 队列）

- 缺页时优先从空闲页框池查找所需页面，若存在则直接复用

- 若不存在则从空闲池分配页框，或淘汰进程驻留集的队首页面

## 七、相关理论与性能优化

### 7\.1 工作集与驻留集

- **工作集**：进程在未来一小段时间内需要使用的所有逻辑页面的集合

- **驻留集**：当前存储在物理内存中的进程逻辑页面的集合

当工作集是驻留集的子集时，进程不会发生缺页。当进程从一个计算阶段过渡到另一个阶段时，工作集会发生变化，导致短暂的缺页高峰。

### 7\.2 抖动（Thrashing）

- **定义**：系统接纳了过多进程，导致所有进程的工作集之和远大于物理内存总容量，所有进程都频繁缺页

- **现象**：CPU 大部分时间用于处理缺页异常，几乎无法执行有效计算，系统性能急剧下降

- **解决方法**：挂起部分进程，将其驻留集全部交换到磁盘，释放物理页框给剩余进程

### 7\.3 预调页技术

- **原理**：一次调入多个相邻的页面，而不仅仅是当前缺页的页面

- **优势**：利用空间局部性原理，减少未来缺页次数，降低磁盘 IO 开销

- **应用场景**：进程启动阶段、大规模数据访问阶段

## 八、总结

请求调页式虚拟存储器是现代操作系统的核心技术，它基于程序局部性原理，通过硬件 MMU 与操作系统内核的协同工作，实现了内存资源的高效利用和进程地址空间的隔离。Unix V6\+\+ 系统的虚拟存储器实现借鉴了 Linux 的设计思想，采用写时复制、共享页缓存等技术，在保证功能正确性的同时，显著提升了系统性能。

页面置换算法是虚拟内存系统性能的关键，实际系统中普遍采用改进型 Clock 算法及其变体，在性能与实现复杂度之间取得了良好的平衡。理解虚拟存储器的工作原理，对于深入掌握操作系统内核机制和进行系统级编程具有重要意义。

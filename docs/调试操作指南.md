# 调试操作指南

## 目标
确认 CopySeg 写入的虚拟地址 0x40B000 在当前页目录中是否有效，如果无效，它是如何不触发 page fault 的。

## 步骤

### 1. 在 NewProc.cpp 中插入魔法断点

`src/proc/ProcessManager.cpp` 第 140 行，在 `while (n--)` 的 CopySeg 循环之前插入：

```cpp
		/* bochs 魔法断点 */
		__asm__ __volatile__("xchg %%bx, %%bx" ::: "bx");

		Diagnose::Write("CopySeg: src=%x des=%x\n", srcAddress, desAddress);
		while (n--)
		{
			Utility::CopySeg(srcAddress++, desAddress++);
		}
```

### 2. 编译并启动 Bochs 调试

```bash
make
bochsdbg -f .bochsrc
```

### 3. 在 bochs 调试器中设置断点

Bochs 遇到 `xchg %bx, %bx` 会自动停下（这是 bochs 内置的 magic breakpoint）。停下后执行：

```
info tab
```

这会打印当前页目录和页表的结构。

### 4. 查看 CR3 和 PDE[1]

```
creg
```

查看 CR3 值。然后手动解析 PDE[1]（CR3 指向的物理页中偏移 4 处的 4 字节）。

如果 PDE[1].Present=1，说明 PDE[1] 被映射了。
如果 PDE[1].Present=0，说明访问 0x40B000 应该 fault，继续追查为何没 fault。

### 5. 继续执行直到 KPF

```
c
```

在 KPF 发生时（`Page Fault in Kernel Mode.`），再执行：
```
info tab
creg
```

对比两次的页表差异，看 PDE[1] 是否在 KPF 前后发生了变化。

### 6. 检查 KPF 时的堆栈

KPF 时 Bochs 会停在 `Utility::Panic` 前。执行：
```
print-stack
```

看调用链 — 确认是哪个上层函数调了 GetBlk，以及传入的 (dev, blkno) 参数。
